# 踩过的坑

真实事故整理，按代价排序。每一条都对应本 skill 里的某个设计。

## 1. 把「一次性豁免」当成长期授权，擅自 push 三个 commit

**经过**：用户某次说「这些就不用询问我了」，指的是当时那批收工事项。后来 AI 在**新一轮、未经本次批准**的功能开发里，直接 commit 并 push 了三个 commit——把一次性的豁免扩大成了永久授权。

**为什么会发生**：规矩只写在文档里，没有任何东西拦得住。

**对策**：`pre-push` 强制校验一次性令牌。没有令牌，物理上推不上去。

**教训**：批准是一次性的、针对具体批次的。**上次批准不延续**，这句话要写进流程。

---

## 2. 把「先出框架」做成完整实现

**经过**：用户说「先出框架」，AI 交付了 13 个动作全部打通 + 29 个测试 + 签名包。等于把用户要做的决策替他做了。

**对策**：流程里加「动手前对齐」——先复述「我理解你要的是 X，范围到 Y 为止，不含 Z」，拿到确认再写；中途要偏离就停下来重新确认。

**教训**：范围模糊的指令（框架/原型/先看看）必须先对齐边界。

---

## 3. 测试安全工具的过程中造成泄密

**经过**：为验证新装的凭据扫描钩子，AI 用**真实口令**做测试串提交，并用 `git reset --hard` 撤销测试提交——结果 `--hard` 把**未提交的钩子改动一并回退成旧版**，钩子失效，测试文件真的进了本地历史。

**处置**：`reset --mixed` 撤回 + `reflog expire` + `gc --prune=now` 清除对象（未推送，远端干净）。

**两条纪律**：
1. 测试串用**伪造内容**，绝不用真实凭据
2. 撤销测试提交只用 `--mixed` / `--soft`，**禁用 `--hard`**

**附带知识点**：只跑 `git gc` 删不掉刚撤回的 commit——**reflog 仍引用着它**。必须先
`git reflog expire --expire=now --expire-unreachable=now --all` 再 `gc --prune=now`。

## 4. 交接文档里的「当前 HEAD」必然漂移

**经过**：文档里写「当前 HEAD=`<sha>`」，每任 AI 都写自己上一笔，累积下来落后 6 笔。更糟的是文档里有**两处** HEAD 字段，AI 自检时用 `grep | head -1` 取到了靠前那处（过期值），误报了一次。

**为什么无解**：任何 commit 都无法在内容里包含自己的 sha（自指循环）。记"最新"永远差 1 笔，记"上一笔"会累积漂移。

**对策**：**文档里不记位置型 sha**，改成「以 `git log -1` 为准」。
**归因型 sha**（"某改动由哪笔完成"）不受此限，照常记录，永久有效。

**教训**：区分「位置型」与「归因型」sha。另外自检不要靠 `grep | head -1` 取样。

---

## 5. 环境时区导致测试假红，误判为产品 bug

**经过**：某时间格式化测试在 UTC+8 环境失败，期望 `10-09 22:04` 实际 `10-10 06:04`，差整 8 小时。一度被当成产品 bug 排查。

**真相**：产品行为正确（ISO 带 Z 的时间转本地时区），是**测试把 UTC 环境的输出写死**了。

**对策**：期望值运行时按 `toLocal()` 现算，任何时区都通过。

**教训**：跑测试固定 `TZ`；遇到"差整数小时"先怀疑时区，别急着改产品代码。

---

## 6. 签到文件被误建进 git 工作树

**经过**：AI 签到时 `cd` 进了仓库目录却用了相对路径 `> CURRENT_AI`，把签到文件写进了工作树内，且未被 `.gitignore` 忽略——任何人跑 `git add -A` 都会误提交。

**对策**：脚本路径**写死在工作区、与 CWD 无关**；并在 `.git/info/exclude` 加一行兜底（本地级忽略，不进版本库，不需要 commit）。

---

## 7. 派生计数一路漂移

**经过**：文档里写「已完成 17/22 项」。真值 24/27。误差来自"上一位的数字 + 我这次的增量"——增量没错，但**基数已错**，误差会逐任累积。

**对策**：**禁止在文档里写派生计数**，要数字就现算（`grep -c`）。
